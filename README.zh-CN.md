# PadPort

![PadPort — 在 Android 上游玩 RPG Maker 游戏。](docs/banner.jpg)

[![下载量](https://img.shields.io/github/downloads/mkaflowski/PadPort/total?style=for-the-badge&logo=github&label=Downloads&labelColor=1a1819&color=d16197)](https://github.com/mkaflowski/PadPort/releases)

在 Android 上使用手柄游玩 **RPG Maker** 游戏。

将电脑上的游戏目录复制到手机、平板或掌机，在 PadPort 中添加后点击“开始游戏”即可。无需转换，也不需要电脑参与运行。PadPort 不会修改游戏文件。

## 功能

- 直接运行原始电脑游戏目录中的 **RPG Maker MV 和 MZ** 游戏。
- 也支持 **RPG Maker XP、VX 和 VX Ace** 游戏（实验性）。
- 支持 **蓝牙和 USB 手柄**，以及 AYN Thor 等掌机的内置控制器。
- 可选的 **屏幕虚拟手柄**，适合触摸屏设备。
- 提供 **按键映射和手柄测试器**，方便查看游戏实际收到的输入。
- 提供 **键盘模式**，适用于只响应键盘输入的游戏。
- **游戏库** 支持使用游戏自带图片、Steam 图片或自选图片作为封面。
- **存档备份**：支持导出存档和重新导入。
- **双屏**：在第二块屏幕上为 *Look Outside*、*To the Moon*、*Fear & Hunger* 和 *Welcome to Elderfield* 显示附加面板，例如在 AYN Thor 上使用（实验性）。
- MV/MZ 游戏可选 **两种浏览器引擎**：PadPort 内置的 64 位 Firefox 引擎 GeckoView（默认），以及 Android 系统 WebView。参见[为什么使用 GeckoView？](#为什么使用-geckoview)。
- 界面支持英语和波兰语，自动跟随 Android 语言设置。

## 运行要求

- Android 8.0 或更高版本。
- 64 位 ARM 设备，近几年的大多数手机和掌机均符合要求。提供下载的 APK 包含 ARM64 原生引擎。
- 自行准备游戏。PadPort 不包含任何游戏。

## 快速开始

1. 从 **[Releases](../../releases)** 下载并安装 APK。如果 Android 提示允许此来源安装应用，请授予权限。
2. 将电脑上的 **完整游戏目录** 复制到设备，例如放到 `Download/Games/Look Outside`。如果游戏是 ZIP 压缩包，请先解压。
3. 打开 PadPort，点击 **添加游戏目录**，选择包含 `index.html` 的目录，或包含 `www` 文件夹的上级目录。系统询问时，请允许访问。
4. 点击 **开始游戏**。

从电脑复制的游戏目录通常包含 Windows 运行时文件，例如 NW.js、Chromium 和 Steam 库，可能占用数百 MB。添加 MV/MZ 游戏时，PadPort 会列出这些文件及其总大小，并询问是否删除。它不会删除游戏数据或存档，删除前也会征求确认。

电脑上的游戏更新后，将新文件覆盖复制到设备，再在游戏卡片的 ⋮ 菜单中选择 **游戏更新后刷新文件**。

## 操作方式

在 Android 设置中配对蓝牙手柄，连接 USB 手柄，或直接使用掌机的内置控制器。大多数 RPG Maker 游戏的默认按键如下：

| 按键 | 功能 |
| --- | --- |
| A / 叉键 | 确认、对话 |
| B / 圆圈键 | 取消、返回 |
| Y / 三角键 | 游戏菜单 |
| L1 / R1 | 上一页 / 下一页 |
| 方向键或左摇杆 | 移动 |

游戏可以自行修改这些设置。如果某个按键没有反应：

- 打开 **控制器 · 映射与测试** 并按下该按键，测试器会显示游戏收到的输入。
- 如果手柄以键盘形式输出，请使用 **映射** 功能设置各个按键。
- 在 AYN Thor 等掌机上，请使用设备的标准手柄模式。系统的触摸映射工具可能会提前拦截按键，使应用收不到输入。

**屏幕虚拟手柄：** 在控制器设置或游玩时的应用菜单中启用 **显示屏幕虚拟手柄**，并通过透明度滑块调整显示效果。

**键盘模式：** 有些游戏只响应键盘。将控制模式切换为 **键盘** 后，手柄按键会发送对应的键盘输入，也可以修改各个按钮对应的键位。

## 双屏

> **实验性功能。** 双屏模式是一项新功能，可能不稳定，也可能导致游戏崩溃。请经常存档；如遇问题，请在游戏的 ⋮ 菜单中关闭此功能，并[提交 Issue](../../issues/new)。

在带有第二块屏幕的设备上，例如 AYN Thor，PadPort 可以在副屏显示附加内容。

![AYN Thor 上的 Look Outside：上屏显示战斗，下屏显示队伍状态和物品按钮](docs/look-outside-thor.jpg)

每个游戏都需要专门制作面板，因此目前仅支持以下游戏：

| 游戏 | RPG Maker | 副屏内容 |
| --- | --- | --- |
| *Look Outside* | MZ | 显示队伍头像、HP、体力、状态和装备，并提供物品栏按钮，可在副屏选择并使用物品。 |
| *To the Moon* | XP | 显示包含人物、笔记和物品的笔记本，点击条目可查看说明。只显示游戏中已经获得的信息。 |
| *Fear & Hunger* | MV | 显示队伍头像、Body 和 Mind、肢体缺失情况、饥饿、恐惧、流血等状态以及装备。战斗中，角色损失 Body 时对应卡片会抖动。仅显示状态，菜单和战斗操作仍在主屏。 |
| *Welcome to Elderfield* | MZ | 显示角色头像（来自角色创建器）、HP/MP、精力、效果、装备、时间、天气和金钱，天空会随时间、季节和天气变化。可从副屏打开游戏物品菜单并使用物品；游戏原有的操作、目标选择和丢弃提示会显示为按钮。 |

添加这些游戏时，PadPort 会询问是否启用副屏。之后也可以随时在游戏的 ⋮ 菜单或游玩时的应用菜单中启用或关闭。战斗指令和游戏自身菜单仍在主屏操作。

希望其他游戏也获得支持？参见[申请游戏支持或双屏模式](#申请游戏支持或双屏模式)。

## 游玩时

- 游戏会在保持原始比例的前提下填满可用空间。屏幕比游戏画面更宽时，两侧会出现黑边。
- 小菜单按钮会在 5 秒后自动隐藏。触摸屏幕或按 Android 返回键可再次显示。
- 应用菜单支持 **导出存档**、**导入存档备份**、显示屏幕虚拟手柄、启用或关闭副屏、复制诊断日志，以及 **返回游戏库**。
- **将屏幕限制为 60 Hz**（默认关闭，仅适用于 MV/MZ）：RPG Maker 游戏以 60 FPS 运行，因此在 90/120 Hz 屏幕上（例如 AYN Thor）启用此项可以节省电量。启用后，游戏中的“不限帧率”选项实际对应 60 FPS。

## 存档

像平时一样在游戏内存档。PadPort 将 MV/MZ 存档保存在浏览器配置中，将 RGSS 存档保存在应用存储中。从游戏库移除游戏会保留存档；重新添加同一目录并使用相同渲染器，即可继续使用。

MV/MZ 游戏的应用菜单还提供 **从游戏目录导入存档** 和 **导出存档到游戏目录**。它们在应用存储和游戏的 `save` 目录（通常为 `www/save`）之间执行一次复制。导入会覆盖应用内的同名存档并重启游戏，源目录文件保持不变。导出需确认后才会覆盖目录中的同名文件，并且需要游戏目录的写入权限。导出复制的是已经保存的存档，不会保存当前尚未存档的进度。正常游玩时不会与该目录同步。

MV 传输包含配置、全局索引、编号存档槽及其备份，并使用游戏自身的文件名和浏览器存储键规则。通过 StorageManager 使用的插件存档槽会在游戏运行过程中被发现；以文件名为基础的槽，只有经引擎确认映射后才会接受。无法映射或存在冲突的文件会在导入前报错。

MV 桌面版存档的全局索引可能保留早期标题：桌面版 MV 忽略该字段，浏览器版 MV 则会校验。目录导入会将实际复制的编号槽在索引中的标题适配为当前游戏标题，包括索引备份，并要求引擎标识一致。其他索引字段和存档槽数据保持不变。索引无效时，会在替换应用内存档之前终止。请使用所选游戏兼容版本的存档；元数据适配不能保证存档数据本身兼容。

MZ 传输使用游戏的 localforage 存储键和 `.rmmzsave` 文件。原有的 JSON 备份导入、导出功能仍然保留。

**卸载 PadPort 或清除其数据会删除保存在应用内的存档。** 请先导出备份。移动游戏目录会改变它在 PadPort 中的标识；需要将存档迁移到其他目录时，请使用导出的备份。

## 为什么使用 GeckoView？

MV 和 MZ 游戏基于网页技术，因此 PadPort 需要浏览器引擎来运行它们。应用提供两种引擎：

- **GeckoView**（默认）：Firefox 引擎。PadPort 内置独立副本，始终以 **64 位** 运行，为大型游戏提供更充足的内存空间。
- **Android 系统 WebView**：Android 内置的浏览器引擎。

GeckoView 默认启用，是因为部分设备（例如 AYN Thor）的 Android 系统 WebView 较旧，并以 **32 位** 进程运行。32 位进程只能使用约 3～4 GB 内存，大型游戏（例如 *Look Outside*）可能因此崩溃并提示“游戏已停止”。Thor 上的 WebView 甚至无法通过 Google Play 更新。

如需切换到 Android 系统 WebView，请打开游戏的 ⋮ 菜单，取消勾选 **使用 GeckoView（64 位引擎）**。此设置会为每个游戏分别保存。

**两种引擎各自保存存档。** 切换引擎后，游戏看不到另一种引擎中的存档。存档并未删除，切回原引擎即可再次使用。需要迁移时，在原引擎中 **导出存档**，再到另一种引擎中 **导入存档备份**。

如果某项功能在一种引擎中正常、在另一种引擎中异常，请[提交 Issue](../../issues/new)。

## 额外兼容修复

部分游戏使用只适用于电脑的扩展。PadPort 对已知情况提供兼容修复：

| 游戏或情况 | RPG Maker | PadPort 的处理 |
| --- | --- | --- |
| *Welcome to Elderfield* | MZ | 修复启动问题，避免 Steam 和插件开关扩展阻止其在电脑以外的平台运行；加载礼物表以支持 NPC 礼物反馈；支持游戏内收音机，包括 *The Weather Channel*。另提供[副屏面板](#双屏)。 |
| 使用 **FOSSIL** 插件的游戏 | MZ | FOSSIL 会在电脑上重写启动页面；PadPort 直接提供相应页面。 |
| 启动时请求 **全屏** 的游戏 | MV/MZ | PadPort 本身已全屏，因此将该请求作为已完成处理，避免游戏因此停止。 |

从电脑复制的目录通常还包含 Windows 运行时文件，例如 NW.js、Chromium 和 Steam 库；*Welcome to Elderfield* 中这些文件约占 540 MB。添加 MV/MZ 游戏时，PadPort 会列出这些文件及大小，并询问是否删除，游戏数据和存档不会被删除。

## 故障排查

- **游戏无法启动或显示错误：** 在游玩时打开应用菜单，选择 **诊断 / 复制日志**，将日志随问题一并提供。
- **游戏自行关闭，提示“游戏已停止”或“Android 为释放内存关闭了游戏”：** 已保存的进度会保留。MV/MZ 游戏可以在 ⋮ 菜单中切换 **使用 GeckoView（64 位引擎）**，尝试另一种引擎。两种引擎的存档相互独立，参见[为什么使用 GeckoView？](#为什么使用-geckoview)。
- **更新前可以运行，更新后出现问题：** 在游戏的 ⋮ 菜单中选择 **游戏更新后刷新文件**。
- **XP/VX/VX Ace 支持属于实验性功能。** 需要安装 RPG Maker RTP 的游戏可能缺少图片或声音，目前不支持 MIDI 音乐和视频播放。
- 部分 MV/MZ 游戏使用特殊的电脑端扩展，可能需要额外支持。反馈时请说明游戏名称。

## 申请游戏支持或双屏模式

请 **[提交 Issue](../../issues/new)** 并提供：

- 游戏名称，如有 Steam 或 itch.io 页面，也请附上链接。
- 游戏使用的 RPG Maker 版本（MV、MZ、XP、VX 或 VX Ace），如已知。
- 设备型号和 Android 版本。
- 具体表现，例如无法启动、在某个位置崩溃，或某个按键没有反应。
- 如果游戏能启动，请附上 **诊断 / 复制日志** 中的日志。

如果希望其他游戏像 *Look Outside*、*To the Moon*、*Fear & Hunger* 或 *Welcome to Elderfield* 一样提供 **副屏面板**，也可以提交 Issue，说明希望副屏显示哪些内容，例如队伍、地图、物品栏或笔记。
